# Pipeline News engine-improvements roadmap

Status: **FUTURE ROADMAP / OUTSIDE V9.6.2 INTERFACE RECOVERY**

This file separates engine work from the copy-first interface repair. None of these items may delay, alter, or silently enter the V9.6.2 recovery release. No automation is created or reactivated by this roadmap.

## Ordered roadmap

1. Stabilise a manifest-first loader so optional intelligence cannot block the base newspaper or project table.
2. Run planning-reference discovery against the governed REPD spine while retaining rule-based identity binding and mandatory abstention for ambiguity.
3. Extend the official-source frontier in small, checkpointed batches and treat rate-limited or degraded sources as non-authoritative.
4. Complete organisation-keyed delivery-role attribution with dated, sourced, coexisting claims; never use person-keyed records.
5. Add deterministic evidence promotion rules that preserve the separation between official facts, discovery, news, planning signals, and attribution.
6. Add field-aware lexical search only after the refreshable corpus and source-health contract are stable.
7. Add engine-level regression fixtures for false bindings, collisions, sentinel projects, degraded sources, and privacy-safe output.
8. Measure freshness, coverage, abstention, and provenance completeness without using those metrics to overwrite government facts.
9. Expose engine changes progressively behind the accepted interface and prove core rendering survives every optional-layer failure.
10. Consider any scheduled execution only under a separate explicit authorisation, with bounded runtime, atomic writes, and a documented disable path.

## Promotion gate

An engine item moves into a product release only after it has its own small build plan, deterministic tests, browser-visible acceptance criteria, source-health evidence, privacy review, and explicit publication authorisation.
